02施工步骤

三个承重旋钮已对代码核验：XROBO_UDP_PORT 在 decoupled_wbc/…/pico/xr_client.py 读取（不在 gear_sonic，grep 别漏目录）；--zmq-port 是 deploy.sh 一等参数；manager 的 --port 即 ZMQ PUB bind 口。

头显 #2 配置（一次性）

装 GameLink（同一 apk——追踪目标在 JSON 不在 dex）→ 开无线 adb → 改配置后重启 app 生效：

adb shell  # /sdcard/Android/data/com.Nolo.CloudVR/files/XrLinkConfig.json
"wholeBodyTracking": { "serverHost": "<host IP>", "serverPort": 63902, "sendControllers": true }

⚠️ 配错端口不报错——两台都打 63901 = 静默混流（见风险 ①）。

manager #2 起第五个终端

cd <GR00T路径>
XROBO_TRANSPORT=udp XROBO_UDP_PORT=63902 PYTHONUNBUFFERED=1 .venv_teleop/bin/python \
  gear_sonic/scripts/pico_manager_thread_server.py --manager --no_auto_pose --port 5566

deploy #2 输入源 keyboard → zmq_manager

G1_LOCAL_ROBOT_ID=2 bash deploy.sh --disable-crc-check \
  --input-type zmq_manager --zmq-port 5566 isaac

ZMQ 输入端口不随 robot id 自动分流（ID=2 只改输出侧），--zmq-port 必须显式给。

bringup 脚本加 PIPELINE_DUAL_PICO=1

deploy#2 换上面的参数并去掉 dk_r2 键管道；追加 manager#2（日志 pico_manager_r2.log）； 删掉脚本里 channel#2 的 ] 发车与 planner 预激活——zmq 模式下发车归操作者 A+B+X+Y，脚本不能代按，wait_for CONTROL marker 不再作为脚本内验收步。

03验收序列——先隔离后联动，别一步到位

Step 1 · 端口隔离

只戴头显 #2

manager#2 停止刷 waiting，manager#1 仍在 waiting = 无串流

Step 2 · 单独发车

头显 #2 A+B+X+Y

sim 日志 channel#2 CONTROL marker received，robot_2 进控制、robot_1 纹丝不动

Step 3 · 双人同时

各自发车各控各机

盯 sync_waits 不涨 + 帧率账本 S 余量（多一个 manager 的 CPU）

Step 4 · 急停语义

任一人 A+B+X+Y

只停自己的 manager，另一路完全不受影响

04风险与边界

① 同端口双发送者 = 静默混流，不报错
xr_client 只留"最新一帧"且不过滤来源——两人身体数据交替覆盖，机器人抽搐。判据：每个 manager 只应看到一个来源 IP；见抽搐先查两台头显的 serverPort。
② sdk / PC Service 模式无设备隔离——pybind 回调写同一组全局变量，双 Pico 只能走 udp 分端口，别试 sdk。
③ feedback 通道对 #2 同样是断的（manager 订 5557/g1_debug vs deploy#2 实发 UDP 5567/g1_2_debug）——只废 FROZEN/VR_3PT 重校准；将来接通时 manager#2 记得 --zmq_feedback_port 5567。
④ planner 退化 bug 双路都在环（各 deploy 一份状态）——任一路行走退化成原地踉跄 = 重启对应 deploy。
⑤ 整场景 reset 不通知输入链（step③ 未验）对双路同样成立；行走演示期间别发 reset。
